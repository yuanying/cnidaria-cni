# ADR 0006: 相手ノードとファミリごとに経路を 1 本、ネクストホップはそのノードの InternalIP

- 状態: 決定（2026-09-19）

## 背景

`host-gw` のデータプレーンは、相手ノードごとに経路 1 本である。このノードは相手ノードの
Pod CIDR に、共有の L2 セグメント上の相手ノードのアドレスへ送ることで到達し、相手ノードの
カーネルが自分の bridge へ転送する。アドレスファミリが 2 つあれば、相手ごとに最大 2 本の
経路になる。入力は Node オブジェクトにある。`spec.podCIDRs` と、`status.addresses` の
`InternalIP` エントリで、後者はファミリごとに 1 つある場合も、1 つしか無い場合もある。

決めるべきは、各ファミリのネクストホップにどのアドレスを使うか、そして片側でファミリが
欠けているときにどうするかである。

## 決定

### ファミリごとに、InternalIP から

相手ノードとファミリのそれぞれについて、デーモンは両方が存在するときに
`<そのファミリの相手 podCIDR> via <そのファミリの相手 InternalIP>` を入れ、どちらかが
欠けていればそのファミリには何も入れない。

- ネクストホップは相手の同じファミリの `InternalIP` である。経路のゲートウェイは on-link
  でなければならず、ノードの InternalIP は定義上そのノードのクラスターセグメント上の
  アドレスである。リンクローカルアドレスは Node オブジェクトが報告するものではなく、
  併せてインターフェースを選ぶ必要が生じる。
- ノードが同じファミリの InternalIP を複数持つ場合は、最初に列挙されたものを使う。これは
  kubelet が報告する順序であり、クラスターの他のすべてが使う順序でもある。
- 出力インターフェースはカーネルがゲートウェイから解決する。ゲートウェイが on-link で
  ない場合 —— 別セグメントのノード —— は経路の追加が失敗し、その失敗はノード名とともに
  ログに出て、他には何も変わらない。`host-gw` は 1 セグメントのためのものであり、その外に
  あるノードはこの設計では到達できない。

### 欠けたファミリは見えるようにし、回避しない

あるファミリの Pod CIDR を持ちながら、そのファミリの InternalIP を持たない相手には、
そのファミリの経路を入れない。デーモンはノード名と欠けているファミリを warning レベルで
ログに出し、状況が変わらないかぎり reconcile のたびに繰り返す。流れて消えないためである。
次のことはしない。

- もう一方のファミリの InternalIP にフォールバックすること（IPv4 のゲートウェイは IPv6 の
  経路を運べず、逆も同じく意味を成さない）
- カプセル化すること（この設計にオーバーレイは無い）
- 失敗を対称にするために、動いている側のファミリの経路を消すこと

タスクが警告する非対称 —— このノードは両方のファミリを持ち、相手は片方しか持たない ——
はまさにこの場合である。規則はこうである。入れられるものを入れ、入れられなかったものを
言う。このノードの Pod は、両側が持つファミリでは相手の Pod に到達し、もう一方では到達
できない。同じ規則で動く相手のデーモンも、このノードへ同じように到達する。これは半分
だけ繋がったペアであり、その warning が、どのノードを直せばよいかをオペレーターに
伝えるものである。黙って全体が繋がっているように見せる設計は、すべてのノードでその
ファミリを落とすことでそうしているにすぎない。

### 所有

経路は cnidaria のために予約したルーティングプロトコル番号を付けて入れ、その番号を
持つ経路だけを回収する。reconcile はノードが持つべき経路の全集合を計算し、欠けている
ものを足し、違うものを置き換え、マーカーを持ちながら集合に無いものを消す。他の誰かが
入れた経路 —— カーネルの connected 経路、オペレーターの静的経路、ルーティングデーモンの
経路 —— は削除候補として列挙すらしない。regied の
[ADR 0009](https://github.com/yuanying/regied/blob/main/docs/adr/0009-ownership-boundary.md)
が求めるとおりである。

デーモンの与り知らぬところで消された経路（運用者が消した、インターフェースが落ちて道連れに
なった）は、次の reconcile が戻す。reconcile は Node のイベントごとに走り、イベントを待たずに
済むようタイマーでも走る。

経路は `ip` を実行するのではなく netlink ライブラリで書く。経路は小さな固定の構造体で、
レンダリングするものも、オペレーターが diff を取るものも無く、ルールセット（ADR 0003）
とは事情が違うからである。

### ノード自身の CIDR

ノード自身の Pod CIDR にはデーモンからの経路は要らない。`bridge` プラグインが `cni0` に
ゲートウェイアドレスを付け、そのプレフィックスに対するカーネルの connected 経路が
それに従う。

## 帰結

- ルーティングのためにデーモンが必要とするのは Node に対する `list` と `watch` だけで、
  それ以外は要らない。Node に書き込むことはない。
- 経路の集合と ADR 0003 のマスカレードのセットは、同じ reconcile の中で同じ Node
  オブジェクトから導出される。したがって、どのノードが存在するかについて両者が食い違う
  ことはない。
- InternalIP が変わったノード（セグメントのアドレスを付け直した場合）は、次の reconcile で
  経路が置き換えられる。ネクストホップは計算されるものの一部だからである。
- netns テストベッド（ADR 0008）は、1 つの「ノード」に IPv4 の InternalIP だけを与え、
  IPv4 で到達できること、IPv6 で到達できないこと、warning が出ていることを確認することで、
  ファミリ欠落の場合を扱う。
